# 商品场景 Agent：低保真交互设计方案

交付文件：`review.html`（总览 / 演示 / 方案三个评审视图）。单文件、内联样式和脚本，无外部依赖，双击即可演示。默认比例 3:4、数量 2 张。此次为框架确认原型，不更改线上官网，不调用 Dify、不消耗生成额度。

## 1. 信息架构

- 首页：产品入口、Slogan + 轻量 IP、自然语言需求输入、参考图入口、紧凑参数、生成。
- Chatflow：按时间排列的用户需求、参考素材、任务状态、Planning / 澄清模块占位、结果图片墙；底部固定修改输入框。
- 图片预览：覆盖当前对话的模态窗口，放大、前后切换、下载、关闭。
- 演示工具：独立灰条，跳转到八种验收状态，并注入下一轮生成失败、下次上传失败；不是产品功能。

对话内保留历史轮次，不另外增加历史管理页面、项目库、账户或跨设备存储。

## 2. 核心流程

首页输入需求 → 上传参考图 → 选择必要参数 → 生成 → Chatflow 展示本轮需求与素材 → 状态及结果占位 → 图片墙 + 3 秒 Toast → 点击预览 / 下载 → 底部输入修改需求 → 新轮次追加，保留前几轮。

商品场景应用要求一张参考图。文字可留空，此时以所选参数和参考图生成默认需求。参数仅保留现有能力：7 种比例、3 种场景、1–4 张数量。文本始终是视觉主入口，参数作为次级紧凑控件；去掉「商品图」等重复标签，通过上传图标、缩略图和无障碍名称表达作用。

## 3. 首页布局

顶部只有产品识别、首页和当前对话入口。主体居中，Slogan 与黑白 IP 位于输入框上方；IP 支持轻量悬停及点击反馈。文本区占主导，上传后在输入区内出现缩略图与移除操作。底部一行承载上传、参数、生成按钮；手机端自然换行。

不设置多 Agent 分类、视频模式、画布、积分、活动、案例内容流或复杂风格系统。「填入示例」用于快速演示，而非商品功能承诺。

## 4. Chatflow 布局

上方为创作标题、返回首页及新建创作。中央是单一纵向对话流：用户气泡靠右，助手过程与图片靠左；首轮带参考图，后续轮次以沿用提示呈现上下文。图片墙桌面和手机均采用两列紧凑展示，比例随本次选择变化。底部输入区固定，内容区预留足够底部空间，避免遮住结果。

生成期间保留输入区位置但禁用提交，避免并发任务；过程只展示状态模块，Planning 和需求澄清保留虚线占位，不设计详细话术。

## 5. 组件与状态

| 组件 | 状态与行为 |
| --- | --- |
| 需求输入 | 空、编辑、就绪、校验错误；长文本换行 |
| 参考图 | 未选择、处理中、缩略图、移除、失败、重新上传 |
| 参数 | 默认 3:4 / 两种都要 / 2 张；提交后与参考图一起形成上下文快照 |
| 生成按钮 | 可提交、图片处理中禁用、当前任务生成中禁用 |
| 任务 | 生成中、准备结果、成功、失败；原型正常流程约 4 秒 |
| 结果 | 按轮次追加，每张可放大和下载；示意图明确标识模拟 |
| Toast | 生成完成出现，3 秒自动消失，不替代持久结果 |
| 图片预览 | 模态层、前后切换、下载、关闭；Esc 关闭，左右键切图，关闭后恢复触发焦点 |
| 修改输入 | 空输入校验、提交追加新轮、生成期间禁用 |
| 失败卡片 | 保留本轮需求与此前成功结果，原位重试本轮 |

## 6. 跳转与交互规则

- 点击生成后进入 Chatflow，使用提交时的文本、素材和参数，后续首页编辑不修改已提交上下文。
- 返回首页保留本次对话，可由「当前对话」恢复。页面内切换不清空结果。
- 新建创作在空闲时重置当前会话，生成中不允许清空。
- 成功时 Toast 自动消失，图片墙持续保留；多轮修改追加新轮次，不覆盖旧结果。
- 上传失败保留文字及已有有效素材，允许重新选择；生成失败只重试失败轮，不重复追加用户消息。
- 预览关闭后回到原轮次，下载由本地浏览器触发。
- 浏览器刷新会重置模拟会话。本版只覆盖单次演示，不提供持久保存。

## 7. 功能边界与正式接入条件

原型模拟上传、生成、图片结果与上下文迭代；不会真正理解修改意图，结果是内嵌灰阶 SVG 占位，不是摄影图。上传仅在浏览器内读取，不发送任何服务器，也不包含 API Key。

现有正式版已支持商品参考图、尺寸、场景、数量、首次生成及下载。自然语言需求、多轮 Chatflow、上下文修改与预览是本次拟确认的交互框架，不能因此认定真实应用已支持。下一阶段需要核验 Dify 能否消费自由文本、沿用 conversation_id、使用上一轮图片并按修改需求重新生成；若工作流不能做到，需要先调整流程。原型不加入局部重绘、抠图、超分、模型切换、视频、画布或其他未支持操作。

正式版已有浏览器压缩至 3 MB 的能力，本次低保真上传只模拟状态，不重复实现压缩逻辑。

## 8. 演示验收

1. 打开 HTML，点击「填入示例需求与参考图」，确认默认 3:4 / 2 张。
2. 点击生成，查看需求与素材保留、过程占位、约 4 秒后的结果和 3 秒 Toast。
3. 点击图片预览，切换、下载、关闭后回到对话。
4. 在底部输入修改需求并提交，查看第二轮及首轮同时保留。
5. 勾选「下轮生成失败」后提交，点击失败卡片「重试本轮」。
6. 勾选「下次上传失败」，返回首页上传文件，查看失败与重新上传。
7. 使用演示状态选择器直达首页、输入、生成中、完成、预览、多轮、上传失败、生成失败；「生成中」为停留展示，切到其他状态即可退出。


## 9. 全页面评审总览

`review.html` 默认展示 9 张线框：首页空状态、首页输入就绪、参数展开、Chat 生成中、Chat 完成与 Toast、单图预览、多轮修改、上传失败、生成失败。每张线框有进入对应交互状态的入口。页面内另附完整设计方案。

附图只有一张“小云雀”长截图，因此仅用其作为结构参考；未假定已看到其他即梦或堆友截图。Slogan + IP 的组合来自用户文字描述，IP 为几何占位，未复制品牌角色。
